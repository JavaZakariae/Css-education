La mise en page, en manipulant

Les parties 1 et 2 répondaient à « quels éléments ma règle touche-t-elle ? ». Celle-ci répond à « pourquoi c'est placé, espacé ou dimensionné comme ça ? ». Chaque leçon est un terrain de jeu : change une valeur à gauche, regarde les boîtes bouger, et lis le CSS généré en dessous.

1

Le box model : quatre couches autour du contenu

Chaque élément est une boîte en couches : le contenu, puis le padding (espace intérieur, il prend la couleur de fond), la bordure, et la marge (espace extérieur, toujours transparent). La question qui piège tout le monde : width mesure-t-il seulement le contenu, ou toute la boîte ? C'est box-sizing qui décide.

box-sizingwidth: 300px veut direConséquence
content-box (défaut du navigateur)le contenu fait 300px, padding et bordure s'ajoutentwidth: 100% + padding = déborde du parent
border-boxla boîte entière fait 300px, le contenu rétrécitce que tout le monde attend
Vérifie ton projetBeaucoup de projets ajoutent en tête de styles.scss : *, *::before, *::after { box-sizing: border-box; }. Si ce n'est pas le cas chez toi, un champ en width: 100% avec du padding dépassera de sa carte.

Le piège Angular : tes composants sont inline

Une balise inconnue du navigateur, comme <app-party-card>, est inline par défaut. Résultat : width, margin-top et les fonds se comportent bizarrement sur l'hôte. Chaque composant devrait décider de son propre display dans :host.

3

Les pièges des marges

margin collapse

Deux marges verticales qui se touchent ne s'additionnent pas : elles fusionnent, et seule la plus grande compte. Ça n'arrive qu'en flux normal (display: block), jamais dans un conteneur flex ou grid. L'écart réel est mesuré en direct ci-dessous.

La solution moderneArrête de mettre des marges sur les enfants pour les espacer. Mets display: flex; flex-direction: column; gap: 16px (ou grid + gap) sur le parent : l'espacement est au même endroit, et aucune fusion n'est possible.
4

overflow : quand le contenu dépasse

Une carte de hauteur fixe contient une liste plus longue qu'elle. overflow décide de ce qui arrive au surplus.

Pour un mat-table dans une carteMets overflow: auto sur un conteneur autour de la table (pas sur la table elle-même), avec une hauteur maximale ou une largeur limitée. La barre de défilement n'apparaît que si nécessaire.
5

Flexbox : tout part de l'axe

display: flex aligne les enfants le long d'un axe principal. justify-content les répartit sur cet axe, align-items les aligne en travers. Si tu changes flex-direction, les deux axes tournent, et les deux propriétés échangent leur rôle visuel.

Le cas réel : l'en-tête d'un dossier

Titre à gauche, actions à droite. Avec space-between et trois enfants, les deux boutons s'écartent l'un de l'autre. La solution la plus simple : margin-left: auto sur le premier bouton. Une marge auto dans un conteneur flex absorbe tout l'espace libre.

7

Le fix le plus utile de flexbox : min-width: 0

Une ligne de partie : avatar, nom, boutons. Avec un nom très long, le nom refuse de rétrécir et pousse les boutons hors de la carte, même avec text-overflow: ellipsis. La raison : un enfant flex a min-width: auto par défaut, il ne descend jamais sous la largeur de son texte. Réduis la largeur, puis passe min-width à 0.

À retenirTexte qui déborde dans un flex ou un grid → min-width: 0 sur l'enfant qui contient le texte. Dans un grid, l'équivalent est minmax(0, 1fr) au lieu de 1fr.
8

Grid : des lignes et des colonnes à la fois

Pour un formulaire en colonnes, grid est fait pour ça. Tu décris les colonnes sur le parent, et les champs s'y rangent tout seuls. fr veut dire « une part de l'espace restant ». Un champ peut s'étendre sur plusieurs colonnes avec grid-column.

grid-template-columns: 1fr 1fr          ┌──────────┬──────────┐
                                          │ Nom      │ Prénom   │
grid-column: 1 / -1  (sur « Rue »)        ├──────────┴──────────┤
                                          │ Rue                 │  ← de la 1re à la dernière ligne
                                          ├──────────┬──────────┤
                                          │ CP       │ Commune  │
                                          └──────────┴──────────┘
La formule magique responsiverepeat(auto-fit, minmax(180px, 1fr)) : « autant de colonnes de 180px minimum que la largeur permet ». Rétrécis le conteneur avec ce choix : les champs passent d'eux-mêmes sur plusieurs lignes, sans media query.

position : sortir du flux

absolute place l'élément par rapport à son ancêtre positionné le plus proche (le premier qui a une position autre que static). Si aucun ancêtre n'est positionné, il part se coller au coin de la page. Essaie de passer la carte en static.

Le pied de stepper qui reste visible

position: sticky; bottom: 0 garde les boutons Précédent / Suivant visibles pendant qu'on fait défiler une longue étape. Défile dans le cadre, puis compare avec static.

Quand sticky ne colle pasUn ancêtre entre l'élément et la zone qui défile a overflow: hidden ou auto. Sticky colle au premier ancêtre qui défile, même si ce n'est pas celui que tu crois.
11

z-index et contextes d'empilement

pourquoi 9999 perd encore

Un menu ouvert dans la carte A doit passer au-dessus de la carte B. Un z-index ne se compare qu'avec les éléments du même contexte d'empilement. Un élément crée un nouveau contexte quand il a une position avec un z-index autre que auto, ou un transform, une opacity inférieure à 1, un filter… À partir de là, ses enfants sont enfermés dedans : même un z-index: 9999 ne peut pas sortir de la carte A.

page
 ├── carte A   z-index: 1  ── contexte ──┐
 │     └── menu  z-index: 9999           │  9999 compte SEULEMENT à l'intérieur de A
 └── carte B   z-index: 2                │
                                         └─ A (1) contre B (2) : B gagne, menu compris
Le lien avec MaterialC'est la raison pour laquelle dialogs, menus et select passent par le cdk-overlay-container en bas du body (partie 2, leçon 6) : ils sortent de tous les contextes de ton écran. Si un overlay passe sous un élément de ton app, cherche un z-index très élevé sur un élément fixe (header, barre latérale).

Container queries : un composant qui s'adapte à sa place

Une media query regarde la fenêtre. Une container query regarde le conteneur du composant. C'est bien plus utile en Angular : le même formulaire peut être large dans une page et étroit dans un dialog. Ici, le formulaire passe à une colonne sous 460px de conteneur, et le titre suit clamp(16px, 5cqi, 30px).

:host {
  display: block;
  container-type: inline-size;
}
.form {
  display: grid;
  grid-template-columns: 1fr 1fr;
  gap: 12px;
}
@container (max-width: 460px) {
  .form { grid-template-columns: 1fr; }
}
