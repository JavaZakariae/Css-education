Les sélecteurs CSS & SCSS, vus de près

Chaque leçon montre un petit HTML à gauche et une vue « boîtes » à droite. Le sélecteur surligne exactement ce qu'il attrape. Dans chaque atelier tu peux taper ton propre sélecteur : tout se recalcule en direct, avec le vrai moteur du navigateur.

Sélectionné : reçoit le style Repère : l'élément qui sert de condition Candidat : stylé seulement dans un état (:hover…) ou via un pseudo-élément
0

Avant de commencer : trois idées qui débloquent tout

Idée 1 · Le HTML est un arbre généalogique

Chaque balise a un parent (celle qui la contient), parfois des enfants (celles qu'elle contient directement) et des frères (même parent). Tous les sélecteurs « relationnels » utilisent ce vocabulaire.

HTML                              L'arbre
<div class="parent">              div.parent
  <p class="child">A</p>           ├── p.child  « A »
  <div class="box">                └── div.box
    <p class="child">B</p>                └── p.child  « B »
  </div>
</div>
MotSignifieDans l'exemple
parentla balise juste au-dessusdiv.parent est le parent de « A » et de div.box
enfantjuste en dessous, un seul niveau« A » et div.box sont les enfants de div.parent
descendanten dessous, à n'importe quel niveau« A », div.box et « B » sont des descendants de div.parent
ancêtreau-dessus, à n'importe quel niveaudiv.parent est un ancêtre de « B »
frèremême parent« A » et div.box sont frères
Le piège n°1« B » est un descendant de .parent, mais ce n'est pas son enfant : son parent est .box. Garde ça en tête pour les leçons 5 et 6.

Idée 2 · Un sélecteur se lit de droite à gauche

Le dernier morceau désigne l'élément qui reçoit le style (le sujet). Tout ce qui est à sa gauche, ce sont des conditions sur l'endroit où il doit se trouver.

  .card  >  .title:hover
  ─────  ─  ────────────
    │    │       │
    │    │       └── SUJET : c'est LUI qui reçoit le style
    │    └────────── combinateur : la relation entre les deux
    └─────────────── condition : où doit se trouver le sujet

Lecture : « un élément .title, survolé, qui est l'enfant direct d'un .card ». Les ateliers affichent cette lecture automatiquement sous chaque sélecteur.

Idée 3 · Ce qu'il y a entre deux morceaux change tout

écrit       symbole    signifie
.a .b       espace  →  .b est à l'intérieur de .a, à n'importe quelle profondeur
.a > .b     >       →  .b est un enfant direct de .a
.a.b        collé   →  UN SEUL élément qui porte .a ET .b
.a + .b     +       →  .b vient juste après .a (même parent)
.a ~ .b     ~       →  .b vient quelque part après .a (même parent)
.a, .b      ,       →  .a OU .b : deux sélecteurs indépendants
Comment utiliser les ateliersClique sur les sélecteurs proposés, ou tape le tien dans le champ « Ton sélecteur ». Survole une boîte pour retrouver sa ligne de HTML, et inversement.
Partie 1

Les sélecteurs CSS, sans SCSS

Ici, uniquement du CSS classique. Tout ce que tu écriras plus tard en SCSS finira transformé en ces sélecteurs-là.

1

Sélecteur d'élément

p · div · span

Tu écris simplement le nom de la balise. Il attrape toutes les balises de ce type, peu importe où elles se trouvent dans la page.

Côté AngularTes composants sont aussi des balises. app-header est un sélecteur d'élément qui vise <app-header>.
2

Sélecteur de classe

.parent · .child

Le point veut dire « qui a cette classe dans son attribut class ». La position dans la page ne compte pas du tout.

Le nom d'une classe ne crée aucune relation.child ne veut pas dire « enfant ». C'est juste un nom, comme .banane. Regarde : le p.child « Hors du parent » est sélectionné aussi. Pour exprimer une relation, il faut un combinateur (espace, >, +, ~).
3

Sélecteur d'ID

#header

Le dièse vise l'élément dont l'attribut id a cette valeur. Un id doit être unique dans la page, donc ce sélecteur attrape au plus un élément.

Pourquoi on l'évite pour le style : un ID « pèse » beaucoup plus lourd qu'une classe quand deux règles se contredisent (c'est la spécificité).

sélecteur        poids (ID · classe · élément)
p                0 · 0 · 1
.child           0 · 1 · 0
p.child          0 · 1 · 1
#header          1 · 0 · 0   ← bat n'importe quel nombre de classes
4

Plusieurs classes sur le même élément

.button.primary

Deux classes collées, sans espace : le même élément doit porter les deux. C'est un « ET ».

   .button.primary
   └──┬──┘└──┬──┘
      └──┬───┘
   le MÊME élément doit avoir .button ET .primary

   <button class="button primary">   ✔ les deux
   <button class="button">           ✘ il manque primary
   <button class="primary">          ✘ il manque button
L'ordre ne compte pas.button.primary et .primary.button donnent exactement le même résultat. Et une classe en plus (large) ne gêne pas.
5

Descendant : l'espace

.parent .child

Un espace entre deux sélecteurs veut dire « à l'intérieur de, à n'importe quelle profondeur ». Enfant, petit-enfant, arrière-petit-enfant : tous comptent.

div.parent  ◀──────── repère
 ├── p.child « Niveau 1 »      ✔ enfant
 └── div.box
      ├── p.child « Niveau 2 » ✔ petit-enfant
      └── div
           └── p.child « Niveau 3 »  ✔ arrière-petit-enfant
p.child « Dehors »                ✘ pas à l'intérieur de .parent
6

Enfant direct : le chevron

.parent > .child

Le > limite à un seul niveau : le sujet doit avoir pour parent immédiat l'élément de gauche. Même HTML que la leçon 5, résultat très différent.

div.parent  ◀──── repère
 ├── p.child « Niveau 1 »      ✔ son parent EST .parent
 └── div.box
      ├── p.child « Niveau 2 » ✘ son parent est .box
      └── div
           └── p.child « Niveau 3 »  ✘ son parent est une div
SélecteurProfondeur autoriséeIci
.parent .child1, 2, 3… tous les niveauxNiveau 1, 2 et 3
.parent > .childexactement 1Niveau 1 seulement
7

Frère adjacent : le plus

.title + .text

Le + vise l'élément qui vient immédiatement après le repère, avec le même parent. Un seul élément par repère, et seulement s'il correspond.

section
 ├── p.text   « Avant le titre »         ✘ avant : jamais sélectionné
 ├── h2.title « Titre »         ─┐
 ├── p.text   « Juste après »   ◀┘ +  ✔ collé juste après
 ├── p.text   « Deuxième texte »         ✘ son voisin d'avant est un .text
 ├── h2.title « Autre titre »   ─┐
 ├── div      « Intrus »         ◀┘ +     le voisin est une div, pas un .text
 └── p.text   « Après l'intrus »         ✘
8

Frères suivants : le tilde

.title ~ .text

Le ~ vise tous les frères qui viennent après le repère, même s'il y a d'autres éléments entre les deux. Jamais ceux d'avant.

section
 ├── p.text   « Avant le titre »         ✘ avant le premier .title
 ├── h2.title « Titre »        ─┐
 ├── p.text   « Juste après »    │ ~  ✔
 ├── p.text   « Deuxième texte » │ ~  ✔
 ├── h2.title « Autre titre »     │
 ├── div      « Intrus »          │     (pas un .text)
 └── p.text   « Après l'intrus » ▼ ~  ✔ l'intrus ne bloque pas
+ ou ~ ?+ = le voisin collé, un seul. ~ = tous ceux qui suivent. Dans les deux cas : même parent, et seulement vers l'avant.
9

Sélecteurs combinés

div.card · div.card.active

Tu peux coller une balise et des classes : div.card = « une div qui a la classe card ». La balise se met toujours en premier. Tout ce qui est collé porte sur le même élément.

div.card.active
│  │    └── et la classe active
│  └─────── et la classe card
└────────── une <div>
→ un seul élément qui remplit les 3 conditions

div .card     ← attention à l'espace : un .card À L'INTÉRIEUR d'une div
10

Sélecteurs d'attribut

[type="text"] · [disabled] · [href^="https"] · [class*="button"]

Les crochets testent un attribut HTML. On peut tester sa simple présence, ou comparer sa valeur.

ÉcritSignifieExemple qui correspond
[disabled]l'attribut existe (peu importe sa valeur)<button disabled>
[type="text"]valeur exactement égaletype="text"
[href^="https"]commence par (^ comme le début d'une regex)href="https://angular.dev"
[href$=".be"]finit par ($ comme la fin d'une regex)href="http://exemple.be"
[class*="button"]contient ce texte, n'importe oùclass="nav-button"
[class~="button"]contient ce mot entier (séparé par des espaces)class="big button"
*= cherche du texte, pas des classes[class*="button"] attrape aussi nav-button et button-primary, parce que le mot apparaît dans le texte de l'attribut. Pour une vraie classe, préfère .button.
11

Pseudo-classes

:hover · :first-child · :nth-child() · :not() · :has()

Une pseudo-classe s'écrit avec un seul deux-points et se colle au sélecteur, comme une classe. Elle ajoute une condition sur le même élément : un état (survolé, focus…) ou une position (premier, dernier, 3e…).

11a · Les états : :hover, :focus, :active

Ces conditions dépendent de ce que fait l'utilisateur. Dans l'atelier, les éléments concernés sont marqués comme candidats : ils reçoivent le style seulement pendant l'état. Essaie pour de vrai dans la démo juste en dessous.

11b · La position : :first-child, :last-child, :nth-child()

Ces pseudo-classes regardent le rang de l'élément parmi les enfants de son parent. li:first-child se lit « un li qui est le premier enfant de son parent ». Ce n'est pas « le premier enfant du li » !

formule             rangs sélectionnés     (n vaut 0, 1, 2, 3…)
:nth-child(2)       2
:nth-child(odd)     1, 3, 5…               = 2n+1
:nth-child(even)    2, 4, 6…               = 2n
:nth-child(3n)      3, 6, 9…
:nth-child(n+3)     3, 4, 5…               à partir du 3e
:nth-child(-n+3)    1, 2, 3                les 3 premiers

11c · Le piège classique : :nth-child() contre :nth-of-type()

:nth-child compte tous les frères, quelle que soit leur balise. :nth-of-type compte seulement les frères de la même balise.

article
 ├── h2  « Titre »         rang 1 parmi les enfants
 ├── p   « Paragraphe 1 »  rang 2 parmi les enfants · rang 1 parmi les <p>
 ├── p   « Paragraphe 2 »  rang 3 parmi les enfants · rang 2 parmi les <p>
 └── p   « Paragraphe 3 »  rang 4 parmi les enfants · rang 3 parmi les <p>

p:first-child      → rien ! le premier enfant est un h2, pas un p
p:first-of-type    → Paragraphe 1

11d · La logique : :not() et :has()

:not(X) exclut les éléments qui correspondent à X. :has(X) garde les éléments qui contiennent X : c'est le seul sélecteur qui regarde vers le bas pour choisir l'élément du haut (« le parent qui a… »).

Dans l'atelierAvec :has(), l'élément trouvé à l'intérieur est encadré en bleu (« condition ») : c'est grâce à lui que la carte est sélectionnée.
12

Pseudo-éléments

::before · ::after · ::first-letter · ::first-line · ::placeholder

Un pseudo-élément s'écrit avec deux deux-points. Il ne sélectionne pas une balise : il cible une partie d'un élément qui n'existe pas dans le HTML (un contenu ajouté, la première lettre, le texte d'aide d'un input…). ::before et ::after créent une boîte à l'intérieur de l'élément, au début ou à la fin, et ont besoin de content.

un deux-points  = pseudo-CLASSE   → une condition sur l'élément   (:hover, :first-child)
deux deux-points = pseudo-ÉLÉMENT → une partie de l'élément       (::before, ::placeholder)
::first-child n'existe pasIl y a :first-child (pseudo-classe, un seul deux-points, leçon 11) et ::first-line / ::first-letter (pseudo-éléments). Le chip p::first-child de l'atelier te montre ce qui se passe : sélecteur invalide, donc le navigateur ignore la règle entière.
13

Le sélecteur universel

*

L'étoile veut dire « n'importe quel élément ». Seule, elle attrape tout. Combinée, elle sert de joker : .box * = tout ce qui est dans .box, .box > * = tous ses enfants directs.

Le classique que tu as sûrement déjà vu*, *::before, *::after { box-sizing: border-box; } applique le même calcul de taille à absolument tous les éléments et à leurs pseudo-éléments.
14

Groupement : la virgule

h1, h2, h3

La virgule veut dire OU. h1, h2, h3 est un raccourci pour écrire trois règles qui ont le même contenu. Chaque morceau entre les virgules est un sélecteur complet et indépendant.

.card h1, h2         se coupe en :   .card h1   OU   h2  ← n'importe quel h2 de la page !
.card h1, .card h2   se coupe en :   .card h1   OU   .card h2
15

La grande comparaison

.parent .child · > · .parent.child · + · ~

Un seul HTML, cinq sélecteurs qui ne diffèrent que par ce qu'il y a entre .parent et .child. Clique sur chacun.

SélecteurSe litRelationRésultat ici
.parent .childun .child quelque part dans un .parentdescendantA, B
.parent > .childun .child directement dans un .parentenfant directA
.parent.childun élément qui a les deux classesmême élémentE
.parent + .childun .child juste après un .parentfrère adjacentC
.parent ~ .childun .child après un .parentfrères suivantsC, D, E
l'arbre                               .parent␣.child  >   .parent.child   +   ~
div.parent  (1er)
 ├── p.child « A »                    ✔           ✔
 └── div
      └── p.child « B »               ✔
p.child « C »                                                          ✔   ✔
p.child « D »                                                              ✔
div.parent.child « E »                                ✔                ✔
Pourquoi E est pris par ~E a la classe .child et vient après le premier .parent (même parent : la page). Le fait que E soit aussi un .parent n'empêche rien.
Partie 2

SCSS : la même chose, écrite en imbriqué

SCSS n'invente aucun sélecteur. Le compilateur Sass (lancé par Angular CLI à chaque build) aplatit ton code imbriqué en sélecteurs CSS de la partie 1. Le navigateur ne voit jamais de SCSS.

16

Le symbole &, très clairement

& = « le sélecteur parent, copié ici »
fichier .scss (imbriqué) ──[ Sass, au build ]──▶ fichier .css (plat) ──▶ navigateur

Toute la transformation tient en deux règles. Retiens-les, elles expliquent 100 % des cas.

Règle 1 · pas de &
PARENT ␣ SÉLECTEUR

Sass colle le parent devant,
puis ajoute un espace.
→ relation descendant
Règle 2 · avec &
chaque & ← PARENT complet

Sass remplace le & par le parent,
exactement à cet endroit,
et n'ajoute rien d'autre.

Ton exemple, pas à pas. À chaque niveau, & vaut le sélecteur complet du bloc qui l'entoure, pas seulement le dernier nom :

.parent {                    → .parent
  .child {                    → .parent␣.child          règle 1 : pas de &, donc un espace
                                  └── ici, & vaut .parent .child
    & span {}                → .parent .child span     règle 2 : & remplacé, l'espace était déjà écrit
    &:hover {}              → .parent .child:hover    règle 2 : collé, donc le MÊME élément survolé
    &.active {}             → .parent .child.active   règle 2 : collé, donc le MÊME élément avec .active
  }
}
SCSS écritCSS généréCe que ça cible
.child dans .parent.parent .childun .child descendant de .parent
& span.parent .child spanun span à l'intérieur de ce .child
&:hover.parent .child:hoverce même .child, quand il est survolé
&.active.parent .child.activece même .child, s'il a aussi .active

Le transformateur : tape du SCSS, regarde Sass travailler

À gauche ton SCSS. À droite, chaque sélecteur imbriqué avec la règle appliquée : le parent recopié est en bleu, l'espace ajouté par la règle 1 apparaît comme ␣. En dessous, clique sur un sélecteur généré pour voir ce qu'il attrape.

    17
    span {} contre & span {}
    c'est la même chose
    
  
    
    
    SCSSsans &
    .parent {
  span { color: red; }
}
    
    
    SCSSavec & et un espace
    .parent {
  & span { color: red; }
}
    
    
    CSS généréidentique
    .parent span {
  color: red;
}
    
  
    
  
    
    
    Les deux donnent exactement le même CSS, dans tous les contextes. Applique les deux règles :
    
    
    Sans & (règle 1) : .parent + ␣ + span = .parent span.
    
    Avec & (règle 2) : on remplace & dans & span, l'espace est déjà là = .parent span.
    
    
    Écrire & span revient donc à écrire à la main l'espace que Sass aurait ajouté tout seul. Le & devient utile uniquement quand tu veux autre chose que « parent + espace » :
    
  
    
  
    
    
    Dans .parent { … }CSS généréSignification
    
    
    span {}.parent spanspan descendant
    
    
    & span {}.parent spanidentique à la ligne du dessus
    
    
    > span {} ou & > span {}.parent > spanspan enfant direct (identiques aussi)
    
    
    &span {}.parentspanune autre classe : plus du tout un span !
    
    
    &:hover {}.parent:hoverle parent lui-même, survolé
    
    
    :hover {}.parent :hovern'importe quel descendant survolé
    
    
    &.active {}.parent.activele parent lui-même, s'il a .active
    
    
    .active {}.parent .activeun descendant qui a .active
    
    
    span & {}span .parentle parent quand il est dans un span (ordre inversé)
    
  
    
  
    La règle à retenirLe & ne change quelque chose que s'il est collé à ce qui suit (&:hover, &.active, &-title) ou placé ailleurs qu'au début (.dark &). Avec & + espace au début, c'est du décor.
    
  
    
  
    Et le CSS natif ?Les navigateurs récents comprennent aussi l'imbrication sans Sass. Là, span {} et & span {} restent équivalents, mais &span ou &-title ne collent pas du texte comme Sass. Dans un projet Angular avec des fichiers .scss, ce sont les règles de Sass qui s'appliquent.

    ★
    Spécial Angular : pourquoi ton style « ne marche pas »
    _ngcontent · :host · ::ng-deep
    
  
    
    
    Par défaut (ViewEncapsulation.Emulated), Angular ajoute un attribut unique à chaque balise de ton template, puis réécrit chaque morceau de tes sélecteurs pour exiger cet attribut. C'est un sélecteur d'attribut (leçon 10) collé à chaque morceau (leçon 9).
    
  
    

    Ce que tu écris dans parent.component.scss
.wrapper span { color: red; }

Ce qu'Angular envoie au navigateur (attribut réel : _ngcontent-ng-c1234567)
.wrapper[_ngcontent-p] span[_ngcontent-p] { color: red; }
         └── seulement les balises écrites dans le template du PARENT

app-child  ← reçoit _nghost-c (son « :host ») et _ngcontent-p (il est dans le template du parent)
  └── span ← reçoit _ngcontent-c : pas _ngcontent-p, donc la règle du parent ne l'atteint pas
    
  
    
  
    
    
    Dans le SCSS du composantVise
    
    
    :hostla balise du composant elle-même (<app-child>)
    
    
    :host(.active)<app-child class="active">
    
    
    :host-context(.theme-dark)le composant quand un ancêtre a .theme-dark
    
    
    :host ::ng-deep .x.x n'importe où sous le composant, y compris dans ses composants enfants (déprécié mais encore très répandu)
    
  
    
  
    
    
    ⚠ Fragile avec &
    :host {
  &.active { border: 1px solid; }
}
/* devient :host.active
   Angular (mode Emulated) le traduit,
   mais ce n'est pas du CSS standard :
   en ShadowDom, ça ne correspond jamais */
    
    
    ✓ Forme standard
    :host(.active) {
  border: 1px solid;
}
:host {
  .title { font-weight: 600; }
  /* → :host .title : OK */
}

    19
    Le grand récapitulatif
    

    SÉLECTEUR
    │
    ├── élément ............. p                 toutes les balises <p>
    ├── classe .............. .card             class="… card …"
    ├── ID .................. #header           id="header"  (unique, très lourd)
    ├── universel ........... *                 n'importe quel élément
    │
    ├── même élément ........ .a.b   div.a     COLLÉ   toutes les conditions sur 1 seul élément
    ├── descendant .......... .a .b             ESPACE  dedans, toute profondeur
    ├── enfant direct ....... .a > .b           >       dedans, exactement 1 niveau
    ├── frère adjacent ...... .a + .b           +       juste après, même parent
    ├── frères suivants ..... .a ~ .b           ~       tous ceux d'après, même parent
    ├── groupement .......... .a, .b            ,       OU : sélecteurs indépendants
    │
    ├── attribut ............ [attr]            présent
    │     ├── [attr="v"]                        égal
    │     ├── [attr^="v"]                       commence par
    │     ├── [attr$="v"]                       finit par
    │     └── [attr*="v"]                       contient
    │
    ├── pseudo-classe ....... :               condition sur le même élément
    │     ├── état            :hover :focus :active
    │     ├── position        :first-child :last-child :nth-child(2n) :nth-of-type(1)
    │     └── logique         :not(.x)  :has(img)
    │
    └── pseudo-élément ...... ::              une partie de l'élément
          └──                 ::before ::after ::first-letter ::first-line ::placeholder

SCSS (imbrication, compilée en CSS ci-dessus)
    │
    ├── .a { .b {} }         →  .a .b        pas de & : parent + ESPACE
    ├── .a { > .b {} }       →  .a > .b
    ├── .a { + .b {} }       →  .a + .b
    ├── .a { & .b {} }       →  .a .b        identique à la 1re ligne
    ├── .a { &.b {} }        →  .a.b         COLLÉ : même élément
    ├── .a { &:hover {} }    →  .a:hover     même élément, survolé
