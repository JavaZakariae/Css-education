Arrête de deviner : inspecte

Lire l'onglet Styles

Styles liste toutes les règles qui touchent l'élément sélectionné, de la plus forte à la plus faible. Une déclaration barrée est battue par une règle plus haut dans la liste. En dessous, les sections « Hérité de… » montrent ce qui vient des ancêtres : la couleur, la police, et surtout les variables CSS.

  • 1Le lien à droite (dossier.component.scss:12) dit d'où vient la règle. En mode développement, Angular fournit les fichiers source : tu sais immédiatement quel fichier modifier.
  • 2Les attributs [_ngcontent-…] dans un sélecteur signalent une règle de composant. Un sélecteur sans attribut vient d'un fichier global ou d'une lib.
  • 3La case à cocher devant chaque déclaration la désactive temporairement : le meilleur moyen de savoir « à quoi sert cette ligne ? ».
  • 4Le bouton :hov force :hover, :focus, :active… sans garder la souris dessus. .cls ajoute ou retire des classes pour tester (compact, active…).
3

L'onglet Calculé : la vraie réponse

Styles montre ce qui est écrit, Calculé montre ce qui est appliqué : une valeur finale par propriété. Clique sur une propriété, ou sur la flèche à côté dans Chrome : DevTools déroule la trace, avec la règle gagnante en premier et les perdantes barrées. C'est le réflexe de la partie 5 : « qui décide de cette taille ? ».

Le schéma du box modelEn haut de Calculé : marge, bordure, padding, contenu, avec les vraies valeurs en pixels. Survole chaque couche : la page la surligne. Pour un « espace mystérieux », c'est le premier endroit où regarder.

Les overlays flex et grid

Dans l'arbre des éléments, un conteneur flex ou grid porte un petit badge flex ou grid. Clique dessus : DevTools dessine sur la page les éléments, les espaces (gap) hachurés et, pour une grille, les numéros de lignes et de colonnes. L'onglet Mise en page (Layout) liste tous les conteneurs de la page avec une case à cocher chacun.

Quand t'en servirTu ne sais pas si l'écart vient d'une marge, d'un padding ou d'un gap ? Allume l'overlay : le gap est hachuré, le reste non. Une colonne de grille plus étroite que prévu ? L'overlay affiche sa vraie largeur.
5

Les variables CSS

Une valeur comme var(--lib-control-height, 40px) ne dit pas d'où viennent les 40px. Dans Chrome, survole la variable dans Styles : une bulle affiche sa valeur actuelle. Clique dessus : DevTools saute à la règle qui la définit, souvent dans une section « Hérité de… » plus bas, posée sur html par le thème ou sur la balise hôte par toi.

  • 1Chaque var(--…) lu par Material ou ta lib est un point de réglage (partie 5, niveau 4). Fais la liste avant d'écrire un override.
  • 2Tu peux ajouter une variable pour tester : clique dans une règle (ou dans element.style) et tape --lib-select-width: 100%.
  • 3Une variable non définie et sans valeur de secours rend la déclaration invalide : DevTools la souligne d'un trait ondulé.

Angular DevTools et la console

Dans Éléments, l'élément sélectionné est disponible dans la console sous le nom $0. En mode développement, Angular ajoute un objet global ng pour relier le DOM à tes composants.

CommandeRenvoie
ng.getComponent($0)l'instance du composant dont $0 est la balise hôte (app-party-card)
ng.getOwningComponent($0)le composant dont le template contient $0 : « qui a écrit ce bouton ? »
ng.getDirectives($0)les directives posées sur l'élément (matInput…)
ng.applyChanges($0)relance la détection de changements après une modification depuis la console
getComputedStyle($0).heightla valeur calculée, sans passer par l'onglet

L'extension Angular DevTools ajoute un onglet « Angular » : l'arbre de tes composants, leurs inputs et leurs propriétés, modifiables en direct. Sélectionne un composant et choisis « afficher dans Éléments » pour retrouver sa balise.

Le lien avec le CSSUn style ne s'applique pas sur un élément ? ng.getOwningComponent($0) te dit à quel composant il appartient, donc dans quel fichier SCSS une règle peut l'atteindre (partie 2). Si la réponse est un composant Material ou de ta lib, tu sais que tu es au niveau 5 de la partie 5.

Inspecter un menu qui disparaît

Ouvre un mat-select, un mat-menu ou un autocomplete, puis clique dans DevTools : le panneau se ferme. La page a perdu le focus, ou a reçu un clic « dehors ». Trois parades :

MéthodeComment
Émuler une page activePalette de commandes (Ctrl+Shift+P) → « Show Rendering » → coche Emulate a focused page. La page croit garder le focus : le menu reste ouvert pendant que tu inspectes.
Pause différéeDans la console : setTimeout(() => { debugger; }, 3000), puis ouvre le menu dans les 3 secondes. La page se fige avec le menu ouvert.
Pause sur modificationClic droit sur div.cdk-overlay-container → Break on → subtree modifications. La page se met en pause dès que le menu s'ajoute ou se retire.
N'oublie pas de décocher« Emulate a focused page » reste actif tant que DevTools est ouvert. Si plus tard un menu ne se ferme plus en cliquant ailleurs, vérifie d'abord cette case.

Corriger en direct, puis reporter au bon endroit

  • 1Essaie dans Styles : change une valeur, coche ou décoche, ajoute une déclaration. Rien n'est enregistré, rien ne casse.
  • 2Ouvre l'onglet Changes (palette de commandes → « Show Changes ») : il liste toutes tes modifications, fichier par fichier, sous forme de diff.
  • 3Choisis le niveau (partie 5) avant de reporter. Une modification faite sur une règle de Material ne se reporte pas dans Material : elle devient un token, une variable ou une règle sur la balise hôte dans ton fichier.
  • 4Retire les attributs Angular : .row[_ngcontent-ng-c3428157] s'écrit .row dans dossier.component.scss.
